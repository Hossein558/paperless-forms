# مستند جامع معماری پروژه Paperless Manufacturing

**نسخه:** ۱.۰  
**فناوری‌های اصلی:** .NET 9, Blazor, Aspose.Cells, DevExpress/Syncfusion  
**پایگاه داده فعلی:** Excel (Shared Network Path)  

---

## ۱. معرفی و اهداف پروژه
هدف این پروژه، تبدیل فرم‌های کاغذی بازرسی خطوط تولید (مانند فرم «بازرسی حین فرآیند تولید») به یک سیستم کاملاً دیجیتال، پویا و مستقل (Standalone) است. این سیستم باید بتواند بدون نیاز به هاردکد کردن فرم‌ها، ساختارهای مختلف فرم را با استفاده از متادیتا پردازش کرده و رندر کند. پیش از این، رویکرد توسعه در بستر Jira بررسی شده بود که به دلیل محدودیت‌های توسعه و نگهداری کنار گذاشته شد.

## ۲. معماری نرم‌افزار (Software Architecture)
پروژه بر اساس الگوی **Modular Monolith** با معماری **Clean Architecture / N-Tier** توسعه می‌یابد. 

### ۲.۱. ساختار لایه‌ای (Layers)
1. **Presentation Layer (UI):** 
   - چارچوب اصلی: **Blazor (Web App)** در .NET 9.
   - دلیل انتخاب: یکپارچگی کامل با زبان C# و امکان بهره‌گیری حداکثری از کامپوننت‌های صنعتی خریداری شده (DevExpress و Syncfusion).
   - وظیفه: دریافت متادیتای فرم از بک‌اند و تولید داینامیک فرم‌ها با استفاده از DataGridها و Form Layoutهای آماده و قدرتمند.
2. **Application / Service Layer:**
   - چارچوب اصلی: **ASP.NET Core Web API / Server-Side Logic** (.NET 9).
   - وظیفه: هندل کردن Business Logic، پردازش اعتبارسنجی‌ها (Validation)، و مدیریت Concurrency.
3. **Data Access / Infrastructure Layer:**
   - واسط ارتباطی: **Aspose.Cells 25.10** (لایسنس معتبر).
   - وظیفه: تبدیل درخواست‌های ذخیره و بازیابی به عملیات خواندن/نوشتن روی فایل اکسل موجود در شبکه (`\\datap2\Atlassian\Jira\sharedhome\paperless forms`). مدیریت قفل شدن فایل (File Locking) در صورت استفاده همزمان کاربران به کمک C# هندل می‌شود.

---

## ۳. پایگاه داده و مدیریت داده‌ها (Database Management)
در حال حاضر پایگاه داده یک فایل Excel است.
- **شیت Master Data:** شامل لیست قطعات، ایستگاه‌های کاری، و ماشین‌آلات (جهت پر کردن Auto-complete ها و Dropdown ها).
- **شیت Form Definitions:** شامل متادیتای فرم‌ها (JSON Schema) که ساختار سوالات، حدود MIN/MAX و روش‌های کنترل را تعریف می‌کند.
- **شیت Submissions:** محل ذخیره پاسخ‌های بازرسان. برای حفظ ساختار پویا، پیشنهاد می‌شود کل داده‌های سابمیت شده یک فرم در قالب یک متن `JSON` در یک ستون مشخص از این شیت قرار گیرد.

---

## ۴. رابط کاربری صنعتی (Industrial UI via DevExpress / Syncfusion)
با توجه به لایسنس‌های موجود (`DevExpress Universal 2025` و `Syncfusion Essential Studio 2025`)، رویکرد فرانت‌اند به شکل زیر خواهد بود:

- **گرید ورود اطلاعات (DataGrid):** برای فرم‌هایی که نیاز به وارد کردن نمونه‌های متعدد در روز دارند (مثل ۵ نمونه بازرسی)، از کامپوننت `DxDataGrid` (در DevExpress) یا `SfGrid` (در Syncfusion) استفاده می‌شود. این کامپوننت‌ها به صورت Built-in از Inline Editing، Batch Update و اعتبارسنجی آنی پشتیبانی می‌کنند.
- **پویایی (Dynamic Rendering):** فرم‌ها از روی JSON Schema ساخته می‌شوند. بنابراین اضافه شدن یک پارامتر کنترلی جدید به یک قطعه، بدون نیاز به کامپایل مجدد سورس کد، به طور خودکار در فرم کاربر رندر می‌شود.

---

## ۵. مزایای این معماری نسبت به رویکرد Jira
1. **سرعت و یکپارچگی:** تمام استک (از فرانت تا بک‌اند) در اکوسیستم قدرتمند .NET 9 و C# نوشته می‌شود.
2. **رابط کاربری پیشرفته:** جیرا فاقد گرید‌های پیشرفته برای ورود داده‌های حجیم صنعتی است. کامپوننت‌های DevExpress/Syncfusion این ضعف را به بهترین شکل پوشش می‌دهند.
3. **مالکیت و کنترل داده:** داده‌ها به طور کامل تحت کنترل شما هستند و در آینده به راحتی می‌توانید موتور دیتابیس را از Excel به SQL Server یا PostgreSQL مهاجرت دهید، در حالی که فقط لایه Infrastructure تغییر می‌کند.
4. **توسعه سریع (RAD):** با استفاده از Blazor Server / Auto، نیازی به طراحی پیچیده API بین فرانت و بک نیست و سرعت توسعه به شدت افزایش می‌یابد.
